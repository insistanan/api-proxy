## 行为约定

- 左侧每个可靠会话一条记录，新请求追加到该会话的时间线。
- 从请求日志跳转时定位会话内对应轮次，完整流量详情按需打开。
- 重发请求保留独立轮次，上游重试归属于原轮次；历史压缩和分支明确区分。
- 保留原始流量日志及 CLI 读取能力，继续遵守正文大小限制和错误传播约定；写入端保留背压，关闭前排空已接收记录。
- 结构调整只增加兼容的数据与接口，不删除或覆盖历史日志。
- 已省略的历史正文无法恢复。新增结构化记录仍需脱敏、去除媒体内容，并限制处理时的内存使用。

## 建议验收

- 同一会话连续发送请求，左侧条目数不变，右侧增加轮次；并行会话不会误合并。
- 超过 200 次请求仍能加载早期轮次，跳转到旧请求可定位。
- 自动刷新不重复下载已经完成且未变化的正文。
- 超过 1 MiB 的请求仍有可读的有界结构化内容；原始正文明确标为已省略。
- 重试、取消、进程中断和历史压缩结果准确；读取损坏数据报错。
- 执行根目录 `npm run check`，前端 `npm test`，以及相关后端日志/代理测试。
