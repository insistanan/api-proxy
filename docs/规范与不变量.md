# 代码规范与关键不变量（conventions）

修改代码前，请先阅读本文。这里记录了项目的代码规范、后端行为约束、前端状态管理方式，以及文档维护规则。

## 1. 全局规范

- 代码注释、文档、提交说明和 CHANGELOG 使用中文。提交信息沿用 conventional commits 前缀，如 feat、fix、refactor、chore 和 docs，具体风格可参考 git log。
- 失败时抛出或返回清晰的错误，不静默忽略异常，也不用默认值掩盖问题。`.gitignore` 中的防御注释记录了历史事故，修改对应规则前要先阅读。
- 改动应围绕实际问题，避免加入暂时用不到的结构。涉及模块边界或行为变化时，应考虑用行为契约测试和静态依赖断言固定约束。
- 提交前需要通过根目录 `npm run check` 或 `make check`。ESLint 使用 `--max-warnings 0`，任何警告都会使门禁失败。
- 注释中的「R1–R6」「方案 7.1/8.1」「Veil ADR 0004」等编号对应已有设计记录，修改相关代码时保留仍有效的编号，背景见 [历史说明.md](历史说明.md)。

## 2. 后端不变量

修改相关代码时须保持以下行为约束：

1. **鉴权三层**：WebAuthMiddleware 只管页面/WebUI 开关，不碰管理业务；管理路由必须在路由组上显式绑定 AdminAuthMiddleware（漏绑会打 `[Auth-Warn]` 警告）；代理鉴权由 RunProxyRequest 或独立控制、模型目录入口调用。密钥提取支持 x-api-key / Authorization Bearer / x-goog-api-key。
2. **shutdown 逆序**：先排空 HTTP 请求，再停数据生产者（scheduler）并等待后台任务退出，最后关闭存储；启动失败与正常关闭共用资源清理登记表，释放错误必须返回，不能中断其他资源的回收。
3. **选渠顺序**：生产请求默认按配置顺序选择渠道。健康的促销渠道可以在组内临时优先，但仍受健康检查和熔断限制，对话路由覆盖的优先级也高于促销。促销不能跨越命中分组与兜底分组的边界；时长或成功次数任一达到上限后，恢复配置顺序。全部渠道不健康时，恢复探测仍按配置顺序进行，性能画像只用于观测。只有开启 Fuzzy 的多渠道请求允许跨渠道故障转移，单渠道和指定渠道请求仍须遵守共享并发与排队限制。
4. **入口与上游协议**：`ChannelKind` 表示入口类型和指标分组，`ServiceType` 表示上游服务类型。共享准入必须使用实际上游协议，不能用入口类型代替，见 `config/config_concurrency.go`。
5. **流式取消传播**：Provider 转换使用 `HandleStreamResponseCtx`，原生转发同样传播请求 context 并关闭上游 body；消费者退出不能留下阻塞的发送 goroutine。
6. **ChannelPermit 生命周期**：取得后 defer 释放，结束时 RecordHealth 恰好一次再 Release，均可幂等重复调用，见 `scheduler/selection.go`。
7. **指标分组与可选存储**：调用 metrics 时必须传入 `apiType`，空串会按 messages 统计。可选存储先通过接口变量传递，避免 typed-nil，见 `main.go` 的 `metricsByKind` 装配。
8. **Provider 实例复用**：Messages→Responses 构建与成功处理必须复用同一实例，保留 previous_response_id 链，见 `handlers/messages/handler.go`。
9. **脱敏模式热切换**：`app_lifecycle.go` 的 `watchMappingStoreMode` 每 15 秒跟随模式；已开始的请求保留快照。block 模式不写入脱敏映射，但映射库仍初始化供热切换使用，拦截记录照常保存。
10. **重启后遗留的 gate waiting 记录按拦截处理**：内存等待者已不存在，启动时由 `GateStore.ExpireStalePending` 标记过期。
11. **配置重载只发布完整候选**：读者只能拿到完整旧快照或完整新快照，见 `config/config_loader.go` 与 `publishConfigLocked`（R3）。
12. **共享准入**：URL、实际上游协议和 API Key 相同的组合，共用最小的配置并发上限，默认值为 5。FIFO 队列最多容纳 3 个请求，单次排队最多等待 10 秒。发布新配置时保留执行计数和队列；失败后先释放名额，重试重新排到队尾。流式请求持有名额，直到 EOF、Close 或取消收尾。本地队列满、等待超时和预算耗尽不能记为上游故障。
13. **重试预算和会话归属**：一个请求最多向上游发送 12 次，累计准入等待不超过 30 秒，辅助推理和兼容重试也计入预算；预算不截断已成功建立的 SSE。429 冷却按凭据组合遵守 Retry-After。Responses response ID 需要持久化记录所属凭据组合；换组合时恢复完整历史，没有可恢复历史则明确拒绝。

## 3. 后端代码风格

- 使用 `fmt.Errorf` 和 `%w` 包装错误，中文消息说明失败原因。启动主流程失败时，按依赖的逆序清理已创建资源。
- 使用标准 `log.Printf`，消息格式为 `[组件-动作] 中文消息`，如 `[Circuit-Init]` 和 `[Auth-Failed]`。运行日志默认写入 `.config/logs.db`，不生成轮转日志文件。
- 包级职责和依赖方向写在 `doc.go` 中，可参考 proxycore、streams、hooks 和 proxy。
- 各存储自行执行建表和列升级 SQL，不使用 ORM 或外部 migration 框架。
- 推理请求发送复用 `internal/httpclient.Send`；模型发现等请求使用独立客户端路径。框架无关重试状态与分类在 `internal/proxy`（有静态依赖断言测试守卫）；原子写一律走 `internal/atomicfile`
- 格式化：gofmt（门禁 `gofmt -l .` 有输出即失败）；无 .golangci.yml

## 4. 前端约定

- **状态归属**：共享领域数据由 store 持有。composable 负责异步流程，也可以持有页面编辑草稿、查询状态和校验结果。草稿与已保存配置分开，取消编辑时不修改 store（R5/方案 8.1）。
- **图标先注册后使用**：vuetify.ts `autoImport: false`，新用 `mdi-*` 图标必须先在 iconMap 注册，`npm run check:icons` 校验
- **视图单根元素**：App.vue 的 `<transition mode="out-in">` 要求路由视图根节点是单个真实 DOM 元素，见 `views/ChannelsView.vue` 的说明
- **五种协议类型（ApiTab）贯穿全栈**：新增协议要同步改 channel store 的 Record、channelApi 工厂、路由参数校验等多处
- **错误语义**：`ApiError.committed`（配置已原子提交但收尾失败）不自动重试，提示用户刷新（useChannelActions.ts，R3 语义）
- **SSE 需鉴权**：用 fetch + `utils/sse.ts` readSSEStream，不用 EventSource
- ESLint 9 flat config：`no-explicit-any: warn`、生产 `no-console: warn` / `no-debugger: error`、未用变量忽略 `^_` 前缀；门禁 `--max-warnings 0`
- 注释用自然、完整的中文说明职责、调用约束和设计原因，保留仍有效的决策编号与必要背景。删除失效计划、注释掉的旧实现和重复说明，但不要省略关键条件。跨文件引用优先使用路径和符号名，避免写入容易漂移的行号；UI 文案使用中文。

## 5. 文档维护约定

- 所有文档放 `docs/`，根 AGENTS.md 只保留导航与精简入口；子项目细节在各自 AGENTS.md
- `CLAUDE.md` 永远只有一行 `@AGENTS.md`（Windows 下 symlink 会退化为纯文本，禁用 symlink 方案）
- CHANGELOG.md 是唯一功能史料，每个版本发布前更新；docs 与 CHANGELOG 冲突时以代码现状为准并修正文档
