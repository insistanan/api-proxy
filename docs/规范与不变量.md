# 代码规范与关键不变量（conventions）

写任何代码前必读。本文分三部分：全局规范、后端不变量（代码中明确注释的约定，违反必出 bug）、前端约定。

## 1. 全局规范

- **全中文**：代码注释、文档、commit message、CHANGELOG 全部中文；commit 遵循 conventional commits 风格前缀（feat / fix / refactor / chore / docs 等，见 git log）
- **不静默兜底**：优先显式抛错 / 返回错误信息，不掩盖问题。`.gitignore` 中多处防御注释源于历史事故，改动前先读注释
- **长期主义**：不为实现而实现；结构性改动考虑补测试（后端有特性测试与静态依赖断言测试两类）
- **门禁**：提交前 `npm run check`（或 `make check`）必须全绿；ESLint `--max-warnings 0` 零警告政策
- **决策编号**：代码注释中的 "R1–R6"、"方案 7.1/8.1"、"Veil ADR 0004" 等编号指向架构优化轮次与决策记录，改动相关代码时保留并延续编号（背景见 [历史说明.md](历史说明.md)）

## 2. 后端不变量（13 条）

以下约定在代码中有明确注释，违反必出 bug：

1. **鉴权三层**：WebAuthMiddleware 只管页面/WebUI 开关，不碰管理业务；管理路由必须在路由组上显式绑定 AdminAuthMiddleware（漏绑会打 `[Auth-Warn]` 警告）；代理端点的 ProxyAuthMiddleware 在 RunProxyRequest 内部调用而非路由层。密钥提取支持 x-api-key / Authorization Bearer / x-goog-api-key。
2. **shutdown 逆序**：先排空 HTTP 请求，再停数据生产者（scheduler）并等待后台任务退出，最后关闭存储；启动失败与正常关闭共用资源清理登记表，释放错误必须返回，不能中断其他资源的回收。
3. **生产选渠默认按配置顺序**，健康促销渠道在所属分组内临时优先，仍须通过健康检查与熔断准入。对话路由覆盖仍优先，促销不跨越命中分组与兜底分组边界；时长和成功请求次数可同时限制，任一达到即结束并恢复配置顺序。全部不健康时，恢复探测按配置顺序进行。性能画像仅观测。只有开启 Fuzzy 的多渠道请求允许跨渠道故障转移；单渠道、指定渠道仍遵守共享并发和排队限制。
4. **ChannelKind ≠ ServiceType**（channel_scheduler.go:37-39）：前者是五协议入口口径，后者是上游服务类型。
5. **流式响应必须用 `HandleStreamResponseCtx`**（带 context），客户端断连立即停读上游，避免 goroutine 泄漏（provider.go:29-32）。
6. **ChannelPermit 生命周期**：取得后 defer 释放，结束时 RecordHealth 恰好一次再 Release，均可幂等重复调用（selection.go:50-58）。
7. **apiType 必须无条件传入 metrics**（空串会被当 messages 口径）；可选 store 收进接口变量避免 typed-nil（main.go:152-159）。
8. **Provider 实例复用**：Messages→Responses 转换时 provider 存进 gin context，成功阶段必须复用同一实例否则丢 previous_response_id 链（messages/handler.go:58-62）。
9. **ContentSafety mask 模式热切换**：watchMappingStoreMode 15s 轮询，已开始请求保留快照（app_lifecycle.go:45-86）；block 模式零落盘。
10. **重启后遗留的 gate waiting 记录一律按拦截处理**（main.go:217-228）。
11. **配置重载只发布完整候选**：读者只能拿到完整旧快照或完整新快照（config_loader.go:104-106，"R3"）。
12. **共享准入**：URL＋实际上游协议＋Key 相同的组合共享最小配置上限，默认 5；FIFO 最多排队 3 个、最多等待 10 秒。配置发布保留执行计数和队列；失败先释放名额，重试重新排到队尾。流式名额持有至 EOF、Close 或取消收尾。本地队列满、超时和预算耗尽不计上游故障。
13. **重试预算和会话归属**：整个请求最多发送上游 12 次、累计准入等待 30 秒，包含辅助推理与兼容重试，不截断成功 SSE。429 按组合遵守 Retry-After。Responses response ID 持久化记录凭据组合归属；换组合后恢复完整历史，无可恢复历史时明确拒绝。

## 3. 后端代码风格

- 错误处理：`fmt.Errorf` 带 `%w` 包装 + 中文错误消息；主流程失败逆序清理资源
- 日志：标准 `log.Printf`，格式 `[组件-动作] 中文消息`（如 `[Circuit-Init]`、`[Auth-Failed]`）；运行日志进 SQLite（`.config/logs.db`），不写文件
- 包结构：遵循"doc.go 声明职责与依赖方向"惯例（proxycore、streams、hooks、proxy 等）
- SQL：手写 SQL + `CREATE TABLE IF NOT EXISTS`，无 ORM、无 migration 框架
- 网络发送唯一出口 `internal/httpclient`；框架无关编排在 `internal/proxy`（有静态依赖断言测试守卫）；原子写一律走 `internal/atomicfile`
- 格式化：gofmt（门禁 `gofmt -l .` 有输出即失败）；无 .golangci.yml

## 4. 前端约定

- **composables 只做编排，状态本体在 store**（唯一来源）——这是 v3.3.0 "状态与异步流程收敛到 composables"（R5/方案 8.1，be1f23c）确立的原则，每个 composable 文件头有中文职责注释
- **图标先注册后使用**：vuetify.ts `autoImport: false`，新用 `mdi-*` 图标必须先在 iconMap 注册，`npm run check:icons` 校验
- **视图单根元素**：App.vue 的 `<transition mode="out-in">` 要求视图根节点是单个真实 DOM 元素，否则路由切换整块空白（ChannelsView.vue:2-11 有注释）
- **五种协议类型（ApiTab）贯穿全栈**：新增协议要同步改 channel store 的 Record、channelApi 工厂、路由参数校验等多处
- **错误语义**：`ApiError.committed`（配置已原子提交但收尾失败）不自动重试，提示用户刷新（useChannelActions.ts，R3 语义）
- **SSE 需鉴权**：用 fetch + `utils/sse.ts` readSSEStream，不用 EventSource
- ESLint 9 flat config：`no-explicit-any: warn`、生产 `no-console: warn` / `no-debugger: error`、未用变量忽略 `^_` 前缀；门禁 `--max-warnings 0`
- 注释风格：文件头职责块注释；store 内 `// ===== 状态 =====` 分节；保留"设计取舍/收敛背景"注释；UI 文案全中文

## 5. 文档维护约定

- 所有文档放 `docs/`，根 AGENTS.md 只保留导航与精简入口；子项目细节在各自 AGENTS.md
- `CLAUDE.md` 永远只有一行 `@AGENTS.md`（Windows 下 symlink 会退化为纯文本，禁用 symlink 方案）
- CHANGELOG.md 是唯一功能史料，每个版本发布前更新；docs 与 CHANGELOG 冲突时以代码现状为准并修正文档
