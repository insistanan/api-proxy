# 规范与不变量

## 通用

- 错误必须显式返回或抛出；Go 用 `%w` 保留错误链，不吞异常或用默认值掩盖故障。
- 改动围绕任务，遵循 KISS / DRY / YAGNI，不增加暂时用不到的抽象。
- 注释说明原因；后端日志用 `[组件-动作] 中文说明`。
- 提交前暂存完整改动并通过根目录全量门禁。行尾遵循 .gitattributes，不手工绕过。

## 后端：改动时不能破坏

| 约束 | 要求 |
|---|---|
| 依赖方向 | 安全、转换和调度不反向依赖 api；通用编解码放 protocol/codec |
| 停机顺序 | 排空 HTTP → 停后台生产者 → 排空日志并关闭数据库；启动失败逆序清理 |
| 选渠顺序 | 默认按配置顺序；健康促销只在同组优先，会话绑定优先于促销；画像不参与排序 |
| 共享准入 | 按实际 URL + 上游协议 + Key 聚合，不能按渠道名计数 |
| 流式资源 | 使用 HandleStreamResponseCtx，传播 Context；断连、成功和失败都及时关闭上游 Body |
| 上游传输 | 共享客户端不跟随重定向，不按错误文本额外重试；流式发送至响应头阶段必须有界，收到响应头后不能用该阶段计时器取消正文 |
| 选渠许可 | 获取 ChannelPermit 后登记 defer Release；每次尝试只记录一次 RecordHealth |
| Responses 会话 | Messages 转 Responses 的 Build 与 HandleSuccess 复用同一 Provider，保留前序会话链 |
| 审核重启 | GateStore.ExpireStalePending 在启动时使遗留 waiting 记录失效，不能误放行 |
| 配置快照 | 原子写入、全量校验后替换；读取方只看到完整旧快照或新快照 |
| 历史 Key 提交 | 先原子落盘完整待同步快照，再写指标库；收尾失败返回 committed，保留可恢复快照，不回滚已提交业务或合并旧库覆盖待同步结果 |
| 脱敏热切换 | 请求绑定时固定安全设置与映射库；输入、响应和流式检查共用该快照，还原未命中审计保留真实请求归属 |
| 脱敏授权与缓存 | 还原只使用本次识别或显式会话授权的映射；新映射使请求改写缓存失效；检测缓存不得冻结旧历史的已知值覆盖 |
| 脱敏性能优化 | 会话缓存每轮核对数据库授权版本与有效期；审计批量同步提交成功后才标记去重；缓存错误不得绕过检查或丢弃审计 |
| 脱敏交付 | 数字、schema 或签名无法安全改写时阻断；工具参数完整校验后交付，未知占位符不得静默交给工具执行 |
| 日志结果 | 分开记录上游状态、客户端 HTTP 状态和处理结果；HTTP 200 不等于流式成功 |

## 前端

- 已保存数据由 Pinia 管理；编辑只改草稿，保存成功再同步，取消丢弃。
- 业务文件放所属 feature，跨业务引用走公开出口；shared 不依赖业务模块，app 负责跨模块流程，契约类型放 types。
- 管理接口走 `shared/services/http.ts`；鉴权 SSE 用 `shared/utils/sse.ts`，不要用原生 EventSource。
- `committed: true` 表示配置已落盘但收尾失败，不自动重试，提示刷新核对。
- 新 mdi 图标先在 `shared/ui/icon/icons.ts` 的 `iconMap` 注册。
- `features/*/views/*.vue` 保留单个真实 DOM 根节点，避免路由切换白屏。
- 提示用 useToast；确认用 useConfirm + ConfirmDialog，禁止 window.confirm；复制用 useClipboard。
- 日期用 `shared/utils/datetime`，图表颜色通过 `shared/theme` 读取，时间范围复用 `useChartPreference`。
- 布局用 Tailwind。颜色、圆角、阴影和表面透明度用 `styles/theme/` 的语义令牌。运行时数值通过组件属性或 CSS 变量传递，Tailwind 类名完整静态书写。
- 新代码使用 `@/` 别名，避免深层相对路径。

## 文档

- CHANGELOG.md 是唯一功能史料；VERSION 是版本号入口。
- 详细文档放 docs；AGENTS.md 保留职责和导航；CLAUDE.md 只写 `@AGENTS.md`。
- 改目录、协议、接口或鉴权时同步相关说明。先找现有文档修改，避免重复建文档。
- 文档保留实际入口、操作和约束。仍影响当前实现的设计动机放在[架构说明](架构说明.md#设计决策)。

## 测试

测试按行为与不变量组织，放在对应模块内。Go 测试的共用夹具可以放在同包的 `_test.go` 文件中。

- 断言可观察的结果、状态、持久化内容和错误语义。包内测试覆盖本层行为，跨层测试覆盖路由、装配和迁移等接线契约。
- 同一规则的多种输入使用 Go 表驱动测试或 Vitest `it.each`。Go 测试命名为 `Test<行为>_<条件>`，前端用 `describe` 和 `it` 描述行为与预期。新增前先搜索已有用例。
- 涉及时钟、超时、退避或随机性的测试注入固定值或可控时间，避免等待真实的秒级超时。
- 移除用例时说明行为由哪条现有用例覆盖。无有效断言的用例应补充断言或清理。
