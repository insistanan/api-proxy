# 开发说明

写代码前读 [规范与不变量](规范与不变量.md)，跨模块改动读 [架构说明](架构说明.md)。

## 环境

- 工具版本见 [技术栈](技术栈.md)。`make` 和提交门禁需要 Node.js 与 npm，Bun 可用于安装前端依赖。
- 首次在 `frontend/` 执行 `npm ci`。修改依赖时同步两份锁文件。
- 后端热重载使用 Air。首次检出或清理产物后，先在根目录执行 `make embed-frontend`，再执行 `make dev`，以便 Go 编译时找到嵌入资源。

## 常用命令

| 位置 | 命令 | 作用 |
|---|---|---|
| 根目录 | `make embed-frontend` | 构建前端并准备 Go 嵌入资源 |
| 根目录 | `make dev` | 同时启动前后端 |
| 根目录 | `make build` | 构建前端、嵌入资源、编译后端到 dist/api-proxy-go |
| 根目录 | `make run` | 构建前端后运行 Go 源码 |
| 根目录 | `npm run check` / `make check` | 全量门禁 |
| frontend | `npm run dev` / `npm run build` | 前端开发 / 生产构建 |
| frontend | `npm run check` / `npm test` / `npm run lint` | 类型与图标 / 单测 / ESLint |
| backend-go | `make dev` / `make test` / `make fmt` | 后端开发 / 单测 / 格式化 |
| backend-go | `./build.sh` | 交叉编译，产物在 backend-go/dist，目标以脚本为准 |

Windows PowerShell 没有 make 时，可在根目录执行以下命令构建当前架构的 exe。

```powershell
npm --prefix frontend run build
node scripts/copy-frontend.mjs
Set-Location backend-go
$env:CGO_ENABLED = '0'
go build -mod=readonly -o ../dist/api-proxy.exe ./cmd/server
Set-Location ..
```

这是本地构建；正式发布还需通过 ldflags 注入 Version、BuildTime、GitCommit，见后端 Makefile 和 release workflow。`VERSION` 是版本号入口。

## 提交前检查

Go 检查依赖嵌入的前端资源。首次检出或清理产物后，先执行 `make embed-frontend`，或者在 PowerShell 中执行上面构建步骤的前两条命令。

先暂存完整改动，再在根目录执行 `npm run check`。门禁依次检查源码跟踪、行尾、嵌套产物、目录登记、gofmt、go vet、Go 测试、前端类型与图标、Vitest、ESLint，最后导出暂存区并重新构建前后端。

隔离构建只复用本机 `node_modules`，可以发现工作区齐全但暂存区漏文件的问题。门禁会把当前仓库的 `core.hooksPath` 设为 `.githooks`，供提交时规范化暂存内容的行尾。测试编写约定见 [规范与不变量](规范与不变量.md#测试)。

## 产物与发布

`frontend/dist` → `scripts/copy-frontend.mjs` → `backend-go/frontend/dist` → webassets.go 的 `go:embed` → 二进制。复制脚本按自身位置定位目录；不要手工复制，嵌套目录只会报错，不会自动清理。

发布使用 version-bump 升版本并提交，推送 `v*` tag 后，Linux / macOS / Windows workflow 构建 amd64 / arm64 的 draft release，再用 github-release 从 CHANGELOG 整理公告。

三个 release workflow 还会将 tag 对应提交中的 `deploy/embedding-presets.json` 和 `deploy/embedding-presets.schema.json` 上传为 Release 附件。只修改 `VERSION` 不触发 workflow；tag 必须指向包含清单的提交。草稿发布为正式的 latest Release 后，客户端继续使用 `releases/latest/download/embedding-presets.json`，无需随版本修改清单 URL。只上传 JSON 清单和 schema，运行时 ZIP、GGUF 模型仍从清单中的资源地址下载。

### 意图匹配与本地向量预设

意图匹配弹窗按“怎么识别任务 / 分组能力 / 试一条”配置，默认选择内置规则；另有向量匹配、辅助模型和混合模式。混合只允许内置+向量、内置+辅助、内置+向量+辅助、向量+辅助，固定按内置→向量→辅助尝试，可靠识别后停止；调用错误按显式失败策略处理。辅助模型仅有 LLM 和 Decisions 两种，协议、分组、渠道通过通用三列选择器逐级选择，模型紧接其后。向量来源在主区域选择本地或 Embeddings 渠道，索引构建保留当前模型配置，不从旧索引自动覆盖。旧手动策略继续保留，路由保护与异常处理默认折叠并说明参数用途。内置 Kilo 免费池保留共享选项及旧四入口渠道 ID。

“试一条”可输入客户端请求模型，展示原模型分组、意图选组及配置中的渠道模型映射，只调用识别所需的辅助模型，不生成任务回答。实际请求的意图分组优先于模型分组匹配，客户端请求模型仍用于渠道内模型映射；人工固定、会话驻留、工具续轮及不透明历史保护优先。未推断出难度时不补成简单任务，只允许声明全部难度的分组接收已识别的任务。

内置起步样本为 `starter-intents-v2`（192 条，index 144 / eval 48）和 `starter-tools-v2`（300 条，index 250 / eval 50）。首次启动时自动保存到本地数据集库，页面直接列出并默认展示第一套样本，无需导入。初始化按内置 ID 记录，已有同 ID 的内容不覆盖，删除后重启也不重建；全部样本仍需审核批准后构建索引，初始化不调用向量模型。

本地助手默认安装在网关启动目录下的 `.config/intent-embedding`，接口与界面展示绝对路径。推荐清单默认使用随二进制附带的 `deploy/embedding-presets.json`，由前端复制脚本一并嵌入，不依赖 GitHub Release 是否已有附件。管理台只展示推荐模型、下载并启动、刷新清单及运行状态，不再提供下载源设置或手动安装表单；相关管理 API 保留兼容。已有自定义清单配置继续生效，拉取使用 HTTPS、10 秒超时、256 KiB 上限，成功结果缓存 10 分钟；失败保留旧清单用于展示并明确报错，安装须等刷新成功，不自动换源。运行时和模型通过推荐项的直链下载并校验 SHA-256。当前一键安装只支持 Windows 的 ZIP 运行时；其他平台没有可用预设时，页面提示使用 Embeddings 渠道。

维护者在 `deploy/embedding-presets.json` 的 `presets` 数组补充经过实测的资源，契约见同目录 `embedding-presets.schema.json`：`version=1`；每项含 `id/name/description/sizeBytes/platforms`，平台键形如 `windows/amd64`、`linux/amd64`、`darwin/arm64`；安装项含 HTTPS 运行时 ZIP 与模型 GGUF 直链、两个完整 SHA-256、ZIP 内 `llama-server` 相对路径（使用 `/`）、模型名称、`cls/mean/last` 池化方式。`sizeBytes` 为运行时与模型的总下载字节数。没有经过核验的资源时保持空数组，页面提示使用已配置的 Embeddings 渠道。当前内置推荐为 `bge-small-zh-v15-q8`（`windows/amd64`，llama.cpp b12383 CPU 运行时 + BGE small 中文 Q8_0 模型，CLS 池化，512 维）。三个发布 workflow 上传清单和 schema，draft 发布为正式 Release 后 latest 下载地址才可使用。

管理接口（均需管理鉴权）：

- `GET /api/intent/local` 返回状态及 `installPath/presetsUrl/phase`，下载、校验、解压、启动、预热均有明确阶段。
- `GET /api/intent/local/presets` 返回当前平台的预设简介、当前清单 URL、默认清单 URL、绝对安装路径和 `error/stale`；URL 为空表示内置清单，自定义清单的拉取错误显式保留。
- `PUT /api/intent/local/presets-url` 接受 `{url}` 保存自定义 HTTPS 清单地址，空字符串恢复默认；保存后清除清单缓存，下次刷新使用新地址。
- `POST /api/intent/local/install-preset` 只接受 `{id}`，后端解析清单并安装、自动启动预热；手动安装仍使用 `/api/intent/local/install`，启动与停止接口保留。网关重启后需手动启动助手。
- `PUT /api/intent/:protocol` 启用向量匹配或包含向量的混合模式时，检查模型运行状态及已发布索引身份。模型未就绪返回 HTTP 409 和 `VECTOR_MODEL_REQUIRED`；模型、渠道、实际映射模型、版本或前缀与索引不匹配返回 `VECTOR_INDEX_REQUIRED`，必须重新构建发布。关闭配置不要求本地模型就绪。`POST /api/intent/:protocol/index-status` 只检查索引，不计算向量；预览与业务检索同样拒绝不同向量空间的比较。

### 数据集存储与本地验证

数据集和向量都保存在网关启动目录下的 `.config/datasets.db`，不是浏览器本地存储，也不是模型安装目录。SQLite 中 `semantic_datasets` 保存元数据与原始样本，`semantic_builtin_initializations` 记录内置样本已完成初始化，`semantic_vectors` 保存按文本和向量空间隔离的单文本向量缓存，`semantic_indexes` 保存已发布索引元数据与 float32 向量。内置初始化使用同一事务，遵守数据集数量与容量上限，失败显式报错并回滚。服务另有有限内存缓存；重启后已发布索引仍可从数据库读取。

前端操作顺序：

1. 在渠道页打开当前协议的意图匹配设置，开启“向量匹配”或选择含向量匹配的混合模式。在“向量模型来源”选择“一键下载本地模型”，再点击“下载并启动”。模型就绪后选择已安装的模型。也可以在同一处选择“使用已配置的 Embeddings 渠道”。
2. 打开“工具与扩展 → 数据集”，直接选择本地数据集，在“样本审核”中检查、批准样本并保存。也可新建或导入自定义 JSON；内置样本无需导入。`index` 样本用于匹配，`eval` 样本仅用于独立评测，意图匹配的构建入口不再自动批准样本。
3. 在“向量索引”选用本地模型，确认模型名称、版本和前缀与业务策略一致，点击“增量构建并发布”。查看样本数、维度、修订和复用数，再执行“检索已发布索引”和“独立评测”。
4. 返回意图匹配设置，选择数据集、配置类别与分组关系，点击“测试匹配”；结果符合预期后保存当前协议。网关重启后需再次启动本地助手，但无须重新导入样本。

后续管理仍在数据集页完成：编辑、增加或撤回批准后先保存，再重新构建发布，业务请求才会使用新修订。模型、版本或前缀变化后应构建对应配置的索引。可以删除某个模型的索引而保留样本，或删除数据集及全部索引；删除前先解除路由或安全策略的引用。单文本缓存独立于数据集，最多保留 8192 条，删除数据集不会逐条删除共享缓存。

“导出 JSON”只导出数据集草稿，不包含已计算向量。需要完整迁移时，停机后备份 `.config/datasets.db`；运行中的 SQLite 可能还有 WAL 数据，不能只复制主文件来保证一致性。

### 渠道思考控制

渠道快捷菜单的“快捷测试”支持“消息测试”和“模型指纹”两种模式，共用模型与思考档位选择。思考档位可选模型默认值、关闭、low、high、xhigh、max；快捷测试使用本次选择，跳过渠道固定的思考策略与模型映射。模型不支持所选档位时明确报错，不自动降档。

“模型指纹”会对所选 URL 和 Key 顺序发送三道数字挑战，使用独立上下文，不受意图路由、模型映射、提示词和安全处理影响；保留渠道的 Codex / Claude Code 伪装、代理、TLS 与共享并发。选择实际的上游模型名称，不使用映射别名。首次检测由后端下载约 3.6 MB 参考数据，缓存到启动工作目录下的 `.config/model-fingerprint/data.bin`，本进程复用已加载的数据版本，不主动执行后台参考库更新；旧版 SDK 默认缓存路径是 Windows 的 `%LOCALAPPDATA%/lmfpd/data.bin`（设置 `XDG_CACHE_HOME` 时使用该目录）。界面不展示伪装实现说明。

检测在后端运行，可点击“后台运行”或直接关闭弹窗；重新进入同一渠道的“快捷测试 → 模型指纹”查看进度和结果，刷新页面不影响任务。每渠道只允许一轮检测同时运行，最近一轮结果与样本保存在 `.config/model-fingerprint/tasks/<渠道ID的SHA-256>.json`，不包含 API Key。服务重启后结果仍可查看，未完成任务标记中断，不自动重发。整轮限时 10 分钟，也可显式停止。样本失败或截断时保留原因，主按钮“重测失败项”只补测失败、截断或已停止的样本，保留成功回答；“重试这一条”仅补测指定样本。如需完整重新采样，在“本轮配置与检测版本”折叠区点击“开始新一轮（3 条）”。部分样本仅给候选排名，置信度仅在 SDK 判断可用时展示。思考档位会影响输出分布，应固定档位重复检测；上游自报型号、排名分数及参考库内置信度都不单独证明模型身份。检测会产生实际上游调用费用。

失败、截断或停止的样本可点击“重试这一条”，只对原挑战重新采样，复用同轮成功样本并重新评分；重试仍在后台运行。重试固定原模型、档位、地址和 Key，不读取当前表单草稿；服务重启后须核验目标配置摘要一致。参考库、评分器或已记录的 SDK 版本变化时拒绝混合重试，应重新开始整轮检测。仅有一两条有效样本时仍可排名，置信度列显示“样本不足”；三条有效样本且置信度校准匹配时才能计算参考库内置信度。

结果中的“本轮配置与检测版本”折叠区展示该轮采样目标、思考档位、SDK 版本、参考库构建时间和数据 SHA-256。SDK 代码固定于 `backend-go/go.mod`，上游发布新 SDK 后需审核差异、升级依赖并重新编译。参考库独立于 SDK 发布，`https://lm.ikale.io/data/bundle.json` 提供 `built_at`、模型列表、`schema`、`detector_schema` 及 `files["shared_detector.bin"].sha256`；与折叠区的数据摘要对比即可核对检测数据是否相同，时间与模型数量仅用于辅助核对。本地加载会校验完整数据的 SHA-256。当前尚无参考库检查或更新按钮，不会因上游发布而自动切换；后续更新应校验兼容性及文件摘要、完整加载后原子切换，新任务使用新版本，旧结果保留原版本记录。

渠道页编辑渠道，在常显的“模型与路由 → 思考控制”选择“跟随请求、自动（模型默认）、关闭、low、high、xhigh、max”，保存后生效。旧配置默认为“跟随请求”。配置字段为 `reasoningEffort`：`inherit` 保留客户端设置，`auto` 清除客户端请求级思考参数且不发送任何思考控制，交给模型默认；`none` 明确发送关闭参数。自动不承诺模型不思考，与关闭不同。此选项适用于对话协议，不用于 Images / Embeddings / Decisions。

关闭只控制发往上游的请求参数，响应仍按协议转换与转发。若客户端仍收到思考块，在“请求与会话观测”的详情查看实际成功的尝试，核对渠道、映射后的模型和“上游请求”里的关闭参数；入口显示的协议不一定是实际使用的上游协议。

选择强制等级后，网关在转换前移除客户端的请求级思考控制，在模型映射和转换完成后按实际渠道协议写入参数；每个候选独立处理，不修改下一候选的输入。原生历史中的 thinking、signature、encrypted_content 和会话链仍遵守已有历史边界与凭据归属规则，思考等级覆盖本身不删除它们。

强制关闭时，之前在思考模式下探测到的“要求原始 reasoning_content”能力不会阻止缺失旧推理原文的请求；已有历史正文仍保留，能力记录不被清除，重新开启思考后继续严格校验。

| 实际上游协议 | 强制参数 |
|---|---|
| Chat / OpenAI | `reasoning_effort` |
| Responses | `reasoning.effort` |
| Claude | 关闭为 `thinking.type=disabled`；其他等级为 `thinking.type=adaptive` 与 `output_config.effort` |
| Gemini 2.5 | `generationConfig.thinkingConfig.thinkingBudget`：关闭 0、low 1024、high 8192、xhigh / max 16384 |
| 其他 Gemini level 模型 | `generationConfig.thinkingConfig.thinkingLevel`，直接发送所选等级 |

这些是渠道策略，不代表模型必然支持所有档位。Gemini 2.5 Pro 和 Gemini 3 无法保证完全关闭；旧 Claude 可能不支持 adaptive，部分模型不支持 xhigh / max。已知无法关闭的情况显式拒绝，其余由上游返回支持范围错误，不省略参数重试或自动降档。Claude 开启思考与强制工具选择冲突时也明确报错。强制策略下禁用 Thinking Signature / Budget 整流重试，避免修改历史或重新开启思考。

跨协议转换不能复用不透明签名。Gemini 历史转 Claude / Chat 时丢弃 `thought=true` 部分，保留普通文本与工具调用；Claude / Chat 回包转 Gemini 时不复制 Claude 签名，也不自动生成 Gemini 占位签名。Gemini 原生回放保留思考、文本及工具 part 的真实签名，显式“移除签名”选项仍可清除它们。已有“注入占位签名”兼容选项只在用户选择后用于原生 Gemini 请求，不作为转换默认行为。

验证时先固定测试渠道，依次保存 high 和关闭，向同一入口发送与渠道策略冲突的客户端等级，并分别检查流式、非流式调用及下一轮工具回传。构建器回归测试会断言最终 HTTP 正文、可重放正文、长度、原输入隔离及原生历史保留；真实上游验证还需查看上游收到的请求和参数支持情况，客户端入站日志中的等级不能单独证明上游最终参数。

### 模型映射与会话稳定性

模型映射区分客户端请求别名和实际上游模型。别名用于选组、查找映射和客户端展示，实际上游模型用于请求正文、URL、能力判断和缓存隔离。

当前项目仍未统一响应模型名：Chat 和原生 Responses 一般沿用上游回包，Messages 流式改写 `model` 的内部选项默认关闭，部分转换路径又使用请求模型名。因此调用方可能从响应 `model` 看到真实模型或渠道前缀，不能承诺 Agent 完全无感知。即使统一改写名字，工具能力、用量格式、错误和思考历史协议也不会因此变成同一种模型能力。

普通调度明确以配置顺序优先，Trace 亲和主要用于观测，不能保证失败切换后持续使用新的渠道。已有 BaseURL 亲和、人工固定渠道，以及意图匹配中的最小驻留与严格历史来源保护；这些不能等同于普遍的会话黏性。人工固定渠道也不独立固定实际模型、URL 和 Key。携带工具续轮或不透明历史时，继续跨来源轮换的风险高于只暴露模型名，可能影响缓存和服务端历史链。

## Docker

`docker compose up -d` 默认使用 `docker-compose.yml` 中的远程镜像。按仓库源码构建时，移除 `api-proxy` 服务的 `image:`，启用示例中的 `build:`，保留 `target: runtime`，然后执行 `docker compose up -d --build`。可在 `build.dockerfile` 选择 `Dockerfile_China`。

单独构建本地镜像时，可选择以下命令之一。

```bash
docker build --target runtime -t api-proxy:local .
docker build -f Dockerfile_China --target runtime -t api-proxy:local-cn .
```

Dockerfile 从 Node 镜像取得工具链，在构建阶段编译前端和 Go，运行阶段只包含生成的二进制及运行依赖。Compose 将 `./.config` 挂载到 `/app/.config` 保存配置和数据库，健康检查使用 `/health`。

## 常见坑

### 对话、日志与 JSON 预览

对话详情支持直接保存名称，并在独立弹窗查看上下文趋势与逐次调用轨迹。日志会话列表的 `GET /api/log-conversations` 返回可选 `name`（实时关联会话注册表）和原有 `title`（首条提示词摘要）；界面优先显示 `name`。无会话记录时保留提示词回退，注册表读取失败仍返回错误。

渠道仪表盘 `GET /api/<协议>/channels/dashboard` 的 `metrics[].activeConversations` 记录该渠道正在处理的独立对话数。同一对话在同一渠道的并行请求或渠道内重试合计为一个，结束后释放计数。渠道页沿用仪表盘刷新周期。

调用统计 `GET /api/request-stats` 按上游尝试聚合。维度排行支持渠道、模型、错误类型、入口协议、状态、上游地址和密钥掩码。统计与 `GET /api/request-logs` 共用时间与筛选口径，`upstream` 和 `keyMask` 为精确筛选。相同掩码会合并统计。

对话轨迹弹窗通过 `provideLogSession` 隔离选择、分页和详情缓存，不读取或清空日志页的全局筛选。模型调用页直接展示逐次尝试，流量详情统一使用 `RequestLogDetail`。

新增 JSON 展示区使用 `frontend/src/shared/components/data/JsonPreviewTrigger.vue` 传入数据、标题和元信息。全局 `JsonViewerDrawer` 在用户登录后挂载。点击 JSON 按钮打开，关闭按钮或 Esc 只关闭当前预览。超过 64 KB 需手动解析，超过 2 MB 可分段查看原文。结构树和搜索达到显示上限时会提示，可单独查看子节点。关闭预览后清除内存中的当前正文。
