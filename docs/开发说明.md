# 开发说明（development）

面向日常开发的操作手册：环境准备、常用命令、门禁、产物链路、发布与部署。规范与不变量见 [规范与不变量.md](规范与不变量.md)，架构见 [架构说明.md](架构说明.md)。

## 环境准备

- Go 1.25（以后端 `backend-go/go.mod` 声明为准，CI 从该文件读取版本）
- Node 20+（release workflow 用 Node 20）；前端依赖本机用 bun 安装（`bun.lock`），CI 同样 bun install；仓库同时存在 `package-lock.json`，改动依赖后注意两份锁文件的取舍
- make（Windows 下若无 make，用 `npm run check` 代替 `make check`——根目录 `package.json` 存在的意义就是摆脱 make/bun 依赖跑门禁）
- 可选：Air（后端热重载）、golangci-lint（`make lint`，仓库无 .golangci 配置文件）
- 本机 Shell 为 Git Bash（POSIX sh），所有命令在 Git Bash 中执行

## 常用命令

| 位置 | 命令 | 说明 |
|---|---|---|
| 根目录 | `make dev` | 后端热重载（Air） |
| 根目录 | `make build` | 前端构建 → copy-frontend → Go 构建，产物 `dist/api-proxy-go` |
| 根目录 | `make run` | 运行当前源码 |
| 根目录 | `make check` / `npm run check` | 全量门禁（见下） |
| 根目录 | `make embed-frontend` / `clean` | 前端产物复制 / 清理构建产物 |
| `backend-go/` | `make dev` / `build` / `check` / `test` / `fmt` / `lint` | 后端各操作 |
| `backend-go/` | `./build.sh` | 跨平台交叉编译（linux/darwin/windows × amd64/arm64） |
| `frontend/` | `npm run dev` / `build` / `check` / `lint` / `test` | 前端各操作 |

开发形态：后端 `make dev`（默认端口 3000）+ 前端 `frontend/` 下 `npm run dev`（默认端口 5173，vite 代理 `/api`、`/v1`、`/v1beta`、`/health` 到 3000）。前端环境变量示例见 `frontend/.env.example`（`VITE_PROXY_TARGET`、`VITE_FRONTEND_PORT`、`VITE_BACKEND_URL`、`VITE_API_BASE_PATH`）。

## 全量门禁（scripts/check.mjs）

**仓库没有 push/PR 触发的 CI，门禁完全依赖本地提交前执行。** `make check` 与 `npm run check` 等价，依次执行：

1. `ensureHooksPath`：确保 `git config core.hooksPath=.githooks`
2. `node scripts/eol.mjs --check`：行尾校验
3. `node scripts/copy-frontend.mjs --check`：嵌套 dist 体检
4. `gofmt -l .`（backend-go，有输出即失败）
5. `go vet ./...` + `go test ./...`
6. 前端 `npm run check`（type-check + 图标扫描）
7. 前端 `npx eslint . --ext .vue,.js,.ts --max-warnings 0`（零警告政策）

## 行尾策略（三层保障）

- `.gitattributes`：工作区统一 CRLF；Go/shell/`.githooks`/`scripts/*.mjs` 强制 LF；`bun.lockb` 二进制 diff
- `.githooks/pre-commit`：提交时调用 `scripts/eol.mjs --staged-fix` 自动修正暂存区行尾
- `scripts/eol.mjs`：`--check`（校验）/ `--staged-fix`（修正）两模式

不要绕过或删除这三层；`.gitignore` 中的防御注释（如 `/skills/` 前导斜杠、嵌套 dist 规则）记录了历史事故原因，改动前先读注释。

## 前端产物链路（唯一权威入口）

```
frontend/dist --(scripts/copy-frontend.mjs)--> backend-go/frontend/dist --(go:embed all:frontend/dist)--> 单二进制
```

- Makefile、backend-go/build.sh、release workflow 全部经由 `scripts/copy-frontend.mjs` 复制，**绝不要手工复制 dist**
- 构建后端前必须先有前端产物（`make build` 自动处理，build.sh 会显式检查）
- 历史上出现过嵌套 dist（`**/backend-go/backend-go/`、`**/frontend/backend-go/`）事故，`.gitignore` 有兜底规则，门禁的 `--check` 模式会体检

## 发布流程

1. `version-bump` 项目技能（`.claude/skills/`）升版本号并提交（同步 `VERSION` 与 CHANGELOG）
2. push tag `v*` 触发三个 release workflow：`release-linux.yml` / `release-macos.yml` / `release-windows.yml`
3. workflow：checkout → Node 20 → bun install/build 前端 → copy-frontend → setup-go（版本取自 go.mod）→ `CGO_ENABLED=0 go build` 注入 ldflags（`main.Version/BuildTime/GitCommit`）→ softprops/action-gh-release 上传 **draft release**（`generate_release_notes: true`），产物覆盖 linux/macos/windows × amd64/arm64
4. `github-release` 项目技能从 CHANGELOG 生成发布公告并更新 draft release

CHANGELOG.md 是中文维护的唯一功能史料，发布前确保其已更新。

## Docker 部署

- `Dockerfile`：三阶段——bun-runtime（oven/bun:alpine）→ builder（golang:1.25-alpine，`make build`）→ runtime（alpine:latest + ca-certificates + tzdata，TZ=Asia/Shanghai，EXPOSE 3000，wget /health 健康检查）
- `Dockerfile_China`：同结构，基础镜像走 docker.1ms.run、apk 源换阿里云、GOPROXY=goproxy.cn
- `docker-compose.yml`：默认拉取阿里云镜像（可切换本地 build）；挂载 `./.config`（配置持久化）与 `./logs`；关键环境变量 `ENABLE_WEB_UI`（true=一体化模式 / false=纯 API 模式）、`PROXY_ACCESS_KEY`（**必改**）、`LOG_LEVEL`、`ENABLE_REQUEST_LOGS`/`ENABLE_RESPONSE_LOGS`；资源限制 256M / 0.5 CPU

## 常见坑

- **图标未注册**：前端新用 `mdi-*` 图标必须先在 `src/plugins/vuetify.ts` 的 iconMap 注册（autoImport: false），否则 check:icons 失败
- **视图多根节点**：App.vue 的 `<transition mode="out-in">` 要求视图根节点是单个真实 DOM 元素，否则路由切换整块空白
- **ESLint 零警告**：`--max-warnings 0`，`no-explicit-any` 只是 warn 也会计入，提交前跑 `npm run lint` 确认
- **修改配置文件**：`config.json` 由 fsnotify 热重载（100ms debounce + sha256 比较），改完无需重启；但运行数据都在 `.config/` 下，测试时注意备份
- **Windows 下不要用 symlink 桥接 CLAUDE.md/AGENTS.md**：git 默认 core.symlinks=false，symlink 检出后变成含链接文本的普通文件，静默失效；用 `@AGENTS.md` 一行引用代替
