# 技术栈总览（tech-stack）

本文列出项目使用的主要依赖、构建工具和运行时组件，供升级依赖或排查兼容问题时查阅。当前版本见 [VERSION](../VERSION)，具体依赖版本以 `backend-go/go.mod`、`frontend/package.json` 和锁文件为准。

## 总体形态

- 单 Go module：`github.com/insistanan/api-proxy`（Go 1.26，工具链 1.26.10），无 go workspace
- 桌面构建：Wails v3.1.0，通过 `desktop` 标签选择入口；Windows/WebView2、macOS/WKWebView、Linux/GTK4 + WebKitGTK 6.0，窗口访问同进程本地 HTTP 管理页面
- 单二进制部署：Vue 3 前端构建产物经 `go:embed` 嵌入 Go 后端，一个可执行文件同时提供代理 API（`/v1`、`/v1beta`）与管理界面（`/api` + 静态页面），默认端口 3000
- 历史：v1.x 为 TypeScript 实现，v2.0.0 起用 Go 重写（见 [历史说明.md](历史说明.md)）

## 后端（backend-go/）

| 类别 | 选型 | 说明 |
|---|---|---|
| 语言 | Go 1.26 / 工具链 1.26.10 | 服务版 `CGO_ENABLED=0`；桌面 macOS/Linux 使用 CGO |
| Web 框架 | gin v1.10.0 | 唯一 HTTP 框架 |
| 数据库 | modernc.org/sqlite v1.44.3 | 纯 Go SQLite（无 CGO）、WAL、手写 SQL；日志库单写连接与最多 4 个只读连接分离，其他业务库通常为单连接；无 ORM 或外部 migration 框架 |
| JSON 操作 | tidwall/gjson + sjson | 避免反复 unmarshal 大 JSON |
| 配置 | fsnotify + godotenv + pelletier/go-toml + yaml.v3 | config.json 热重载（debounce + sha256 摘要比较） |
| 压缩 | klauspost/compress + andybalholm/brotli | 上游响应多算法解压 |
| SSE | 业务解析与转发手写（`utils/sse.go`、`handlers/streams`、`providers`） | `gin-contrib/sse` 是 Gin 的间接依赖；无 WebSocket 功能 |
| 测试 | stretchr/testify + 原生 testing | 行为契约、并发与资源生命周期测试，以及静态依赖断言 |

## 关键运行时组件（后端 internal/ 摘要）

| 组件 | 职责 |
|---|---|
| `handlers/proxycore` | 通过 `RunProxyRequest` 编排五协议主请求，各协议由 `ProtocolSpec` 提供差异逻辑 |
| `converters` | OpenAI/Gemini/Responses/Claude 请求、响应与流式事件转换，按协议和转换阶段分文件 |
| `providers` | Provider 接口 + openai/gemini/claude/responses 四实现 |
| `scheduler` | ChannelScheduler 多渠道调度 + ChannelPermit 许可句柄 |
| `circuit` / `upstreamcontrol` / `urlhealth` | 渠道级三态熔断 / 按凭据组合共享并发、FIFO 排队、429 冷却与请求预算 / 多 BaseURL 健康管理 |
| `sensitive` / `llmgate` / `handlers/hooks` | 敏感数据检测与可逆脱敏 / 危险命令 AI 闸门 / 内容安全三阶段钩子管线 |
| `session` / `conversation` / `metrics` | Responses 会话与 Trace/BaseURL 亲和 / 对话注册表 / 按 ChannelKind 指标与 SQLite 持久化 |
| `assistant` / `skills` | AI 配置助手 / Agent Skill 目录管理 |
| `config` / `httpclient` / `proxy` / `atomicfile` | 配置热重载 / 客户端管理与推理请求发送 / 框架无关重试状态与分类 / 原子写原语 |

完整架构与请求流转见 [架构说明.md](架构说明.md)。

`internal/ratelimit` 保留了旧滑动窗口限流实现和测试，当前生产链路不再调用。现行请求准入由 `upstreamcontrol` 负责，阅读调度代码时应以它的规则为准。
