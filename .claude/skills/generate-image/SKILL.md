# 生图与提示词

使用 5S 组织提示词。图片保存到目标项目的 `temp/images/`，向用户展示图片入口和绝对路径。脚本 JSON 默认不展示。

## 先选模式

| 用户意图 | 动作 |
|---|---|
| 生成或修改图片 | 形成 `--prompt`，跑脚本 |
| 编写或优化提示词 | 组织提示词，不跑脚本 |
| 给图反推、拆图、「这张图怎么画」 | 根据可见事实组织提示词，不跑脚本 |
| 明确要求先反推再生图 | 先反推，再按下方参考图规则决定是否传 `--image`，最后跑脚本 |

根据最终交付目标判断是否出图，不凭单个关键词触发。给图询问提示词或 5S 时只反推；明确要求画、生成、改图时才调用接口。

参考图是否传给脚本，取决于要保留的视觉信息：

- 用户要求编辑原图、保脸、保留身份或原图构图，或明确把图片作为视觉参考时，传 `--image`。
- 用户明确要求纯文生图、只按反推文字重新画，或明确不要参考图时，不传 `--image`。
- 「复刻」本身不决定接口。有原图且要保留其视觉特征时用参考图；只给文字时按文字生成。两种理解会明显改变结果且上下文不足时再询问。

写提示词前读取 [references/5s.md](references/5s.md)。用户点了风格名或编号时，再读取 [references/styles.md](references/styles.md)。

## 硬规则

- 生图/改图只跑脚本，禁止自己 curl、自己解码 base64。图片数据很大，进对话会撑爆上下文。
- 参考图只传本地文件路径。可以看图做反推或确认画面，但不把图片字节、base64 或像素贴进对话，也不手写转发给接口。
- 脚本成功时 stdout 是一份 JSON，按「用户回复」展示；只有用户要求 JSON 或调试信息时才提供相关字段。
- 失败时读取 `ok: false` 和 `error`。异常退出且没有 JSON 时，明确说明实际错误，不把空输出当成成功。不改调其他生图接口，不自动重试。
- 用户没提尺寸、质量、格式时只用默认值，不擅自改；可以给出建议。
- 跑脚本前在内部形成最终 `--prompt`，默认不先向用户展示全文或要求确认。
- 只要提示词或反推时不出图，不额外保存为文档。
- 反推时不贴 base64，不擅自出图，不为反推把图复制到 `temp/`。

**参考图来源**：

1. 用户消息里已有附件路径（拖入、粘贴、明确写出）→ 原样传给 `--image`。
2. 生图/改图时只有画面、没有路径（例如纯粘贴截图）→ 停下来问用户要文件路径。反推可以直接看对话里的图，不必先要路径。
3. 不把参考图复制到 `temp/`，脚本直接读原文件。
4. 反推时若用户只说「去网上找某张图再反推」，且本地和对话里都没有图，停下来要路径或附件，不用搜索结果顶替原图。

## 默认值

用户没说就用这些：

| 参数 | 默认 |
|---|---|
| 尺寸 | 1K 1:1 → `1024x1024`；GIF 未指定时用 `512x512`（见下） |
| 质量 | `auto` |
| 张数 | `1` |
| 格式 | 不发送，跟随网关渠道；渠道未固定时使用上游默认 |
| GIF 帧数 / 每帧时长 | 不发送，跟随渠道；管理表单建议 9 帧 / 200 毫秒 |
| 背景 | `auto` |
| 审核 | `auto` |
| 输入保真 | 不发送（默认） |

**GIF 尺寸例外**：GIF 的多帧要拼进同一张画布，上游有像素预算限制。9 帧 × 1024x1024 超出预算时上游会退化成静态图或直接报错，所以 GIF 未指定尺寸时用 `512x512`；用户明确给了尺寸就按用户给的传。

## 自然语言 → 参数

从用户的话里抽出覆盖项，没提到的保持默认。分辨率、比例、质量档位、格式、张数等控制值只进 CLI；「高级感」「柔和光线」属于视觉要求，不能当作 `--quality high`。透明底用 `--background transparent`，需要独立主体、完整轮廓等画面安排时，在提示词里写明这些视觉要求。

| 用户说法 | 发给脚本 |
|---|---|
| 没说尺寸 / 方图 / 正方形 | 不传，默认 `1024x1024` |
| 1K / 2K / 4K | `--tier 1K` / `--tier 2K` / `--tier 4K` |
| 16:9、9:16、3:2、2:3、4:3、3:4、21:9、横图、竖图、宽屏 | `--ratio 16:9` 等；横图=`16:9`，竖图=`9:16` |
| 1K 且 16:9 | `--tier 1K --ratio 16:9` |
| 直接说 `2048x2048` | `--size 2048x2048` |
| 自动尺寸 | `--size auto` |
| 质量 auto/low/medium/high；低质量、高质量、最高 | `--quality auto/low/medium/high`；最高也用 `high` |
| 两张、n=3 | `--n 2` / `--n 3`（1-10） |
| PNG / JPEG / WebP / GIF / SVG | `--output-format png/jpeg/webp/gif/svg` |
| GIF 动图、循环动画 | 默认显式传 `--output-format gif`；只有明确知道渠道已固定 GIF 时才可省略 |
| 12 帧 / 每帧 100 毫秒 | `--frame-count 12` / `--frame-duration-ms 100`（仅 GIF） |
| JPEG 压缩率 80 | `--output-format jpeg --output-compression 80` |
| 透明底 / 不透明 | `--background transparent` / `--background opaque` |
| 审核放宽 / low | `--moderation low` |
| 参考图要更像原图 / 保真高或低 | `--input-fidelity high` / `--input-fidelity low`（仅改图） |

尺寸由脚本内置的 `SIZE_PRESETS` 映射，直接传 `--tier` 和 `--ratio`，不自行换算或修改预设。用户给出明确像素尺寸时用 `--size`。

网关固定的输出格式优先于 CLI；渠道 GIF 帧数和时长只有配置为非零时才覆盖请求，留空则沿用请求或上游默认。渠道已配置 GIF 时，不必再要求用户手写参数；要让 CLI 控制格式和全部帧参数，渠道应选择「跟随请求」。GIF/SVG 能否生成由上游模型决定，技能不把静态图片转换成动画。

## GIF 怎么生成

用户要求动画时，提示词写明主体动作、动作先后、镜头是否固定以及是否循环；同时按渠道配置选择参数：

| 渠道「输出格式」 | 脚本参数与实际效果 |
|---|---|
| 跟随请求，或不知道渠道配置 | 显式传 `--output-format gif`；用户指定帧数或时长时再传对应参数 |
| GIF 动图 | 可以省略 `--output-format`；渠道非零帧参数覆盖 CLI，未配置的帧参数沿用 CLI 或上游默认 |
| 静态 PNG / JPEG / WebP 或 SVG | 固定格式会覆盖 `--output-format gif`；需要使用跟随请求或 GIF 渠道 |

| CLI | Images 请求字段 | 含义与范围 |
|---|---|---|
| `--output-format gif` | `output_format: "gif"` | 要求 GIF 文件；只在提示词写「动画」不能保证此格式 |
| `--frame-count 9` | `frame_count: 9` | 一个 GIF 的帧数，整数 2–16 |
| `--frame-duration-ms 200` | `frame_duration_ms: 200` | 每帧显示时长，至少 20 毫秒；Responses 渠道最多 2000 毫秒 |
| `--n 2` | `n: 2` | 生成两个独立文件，不是两帧；Responses 渠道只支持一张 |

一轮动画时长约为 `帧数 × 每帧毫秒数 / 1000` 秒。例如 9 帧 × 200 毫秒为 1.8 秒，约 5 fps；12 帧 × 100 毫秒为 1.2 秒，约 10 fps。帧数控制动作采样数量，每帧时长控制播放速度。9/200 是管理表单建议值，脚本不会自行补发这两个值；未指定时由渠道或上游决定。

文生 GIF 走 `/v1/images/generations`；加 `--image` 参考图则走 `/v1/images/edits`，同样可以传 GIF 参数。GIF 不支持 `--mask`、`--output-compression`。原生 Images GIF 使用非流式 JSON，Responses 转换由网关负责；脚本无需切换到 `/v1/responses`。

交付时按实际文件内容识别后缀。如果请求 GIF 却实际保存为 PNG/JPEG/WebP，明确说明返回了静态图片，检查渠道固定格式和上游能力，不能把静态文件改名成 GIF 或宣称动画已完成。识别为 GIF 只说明容器格式，不保证多帧或首尾衔接；需要检查实际动画效果。

脚本在成功时额外给出校验结果，用来区分「上游不支持」和「提示词没写清楚」：

| 字段 | 含义 |
|---|---|
| `warnings` | 出现即说明结果与预期不符，必须在回复中转达，不能当作完全成功 |
| `images[].frames` | GIF 真实帧数；`1` 表示只是单帧静态图包装成 GIF |
| `images[].loop` | GIF 是否带循环标记 |

常见 `warnings` 与处置：

| 警告 | 含义 | 处置 |
|---|---|---|
| 请求 `output_format=gif`，实际返回 png | 上游忽略了格式参数，或渠道固定了静态格式 | 换渠道或改用跟随请求的 GIF 渠道；不改提示词重试没有意义 |
| GIF 只有 1 帧 | 上游出了静态图 | 同上，按静态图交付并说明 |

上游是否愿意出 GIF 还受提示词影响：写明「循环」「seamless loop」「首尾衔接」并给出具体动作时更容易拿到多帧 GIF；只写「 waving」这类静态描述时，上游常直接返回静态图。所以在请求 GIF 时，提示词必须包含可循环的动作描述。

## 提示词要点

5S 是内部组织画面的方法，最终提示词是自然语言，不展示内部核对过程，不固定套用五个小标题。用户要求原样沿用时，不改写正文，只提取输出参数。提示词语种跟用户；风格词库的英文特征可译成对应视觉描述。

1. **确定目标和硬约束。** 提取用途、视觉重点、主体、必须保留或修改的内容、图内文字及禁止项；分离 CLI 参数。用途不影响执行时不追问。
2. **按 5S 整理。** 把已有要求和必要的参考图事实对应到主体、风格、镜头与构图、场景、光照。区分明确要求、参考事实、必要补充和未指定项，不要求每项都有内容。
3. **协调五个维度。** 构图承载主体和用途，场景与光照服务视觉重点，风格落在材质、线条和着色上。按 `references/5s.md` 检查冲突，不只判断五项是否齐全。
4. **组织自然提示词。** 可调语序、合并重复、明确指代；只补实现意图所需的视觉信息，不新增主体、事件、人物关系、背景故事或象征意义。
5. **核对成稿。** 检查遗漏、擅自增加、参考范围、图内文字和禁止项，以及画面描述与 CLI 参数是否相容。仅在关键歧义会明显改变结果时询问。

优先级：用户明确要求和禁止项 > 参考图保留范围及其可见事实 > 助手的必要补充。低优先级内容冲突时删除或调整；用户的硬要求互相冲突时，说明冲突并询问，不静默舍弃。

- 专有名没有可靠外形信息时，以用户文字和参考图为准，必要时用中性描述，不编造「公认设定」。
- 抽象要求转换成直接对应的可见特征，不附加价值判断或审查口吻；不为了填满 5S 编造场景或镜头。
- 参考图按用户指定范围继承：可只参考脸部、服装、姿态、构图、色彩、材质或画风。只改背景或明确「其他不变」时保留其余可见内容；只参考画风时不复制人物和场景。融合、变形或重设计按用户原话执行。
- 只有用户明确说「继续、保持上一张、基于上一版修改」等，或意图包含对前图的修改时，才继承上一张未改的设定；普通新请求重新解析。
- 有明确用途（头像、设定稿、海报、包装、界面）时，补充该用途必需的版式信息；不擅自增加文案、分区或品牌元素。
- 点名风格时按 `references/styles.md` 选取适用特征，不整串复制；涉及构图、场景和光照的词回到对应维度判断。用户要求混合风格时保留混合；未指定时不套风格词库。不用在世作者名作为风格标签，改用可观察的线条、色彩、笔触和材质描述。
- 图内文字：用户给出的文字用引号并写清位置与排列；未要求时不添加无关的可读文字、标题、标识或水印，场景中自然存在的招牌、路牌不必排除。
- 不改掉用户点名的主体、服装、姿态、文案和禁止项，不把 A 画成 B。品牌只借鉴版式或配色，除非用户明确要求，不凭空添加商标或品牌字样。
- 反推只用图片可见事实：优先写可识别的外形、服饰、姿态、构图、媒介和光照；看不清的细节或文字不猜写；不猜身世、剧情或精确摄影参数。
- 设定图或多姿态反推默认还原整板，保留版式、各姿态、编号与标题位置及细节特写区的对应关系；用户明确只要某一姿态或某个局部时，再收窄到该姿态或局部。
- 反推默认只回提示词代码块；用户要求分析或拆解时再附对应内容。
- GIF 提示词保留动作、动作先后和循环要求；用户要求循环时可写明首尾衔接。帧数与每帧时长放在 CLI 或渠道配置，不能只靠提示词保证动画格式。

## 调用

把 `SKILL_DIR` 换成本 skill 的绝对路径。`--name` 用短词干（主题或角色名，不超过约 8 个汉字 / 16 个字母），不要把提示词当文件名。

不带参考图：

```bash
node "<SKILL_DIR>/scripts/generate.mjs" --prompt "<提示词>" --project "<项目根目录>" --name "<短词干>"
```

用户指定参数，例如「2K 16:9 高质量 JPEG」：

```bash
node "<SKILL_DIR>/scripts/generate.mjs" --prompt "<提示词>" --project "<项目根目录>" --name "<短词干>" --tier 2K --ratio 16:9 --quality high --output-format jpeg
```

已知渠道固定 GIF 时（使用渠道里的格式、帧数和时长）：

```bash
node "<SKILL_DIR>/scripts/generate.mjs" --prompt "猫咪挥手的循环动画，固定镜头，动作连贯，首尾自然衔接" --project "<项目根目录>" --name "挥手猫"
```

渠道跟随请求时，例如用户要求「猫咪挥手，9 帧，每帧 200 毫秒，循环」：

```bash
node "<SKILL_DIR>/scripts/generate.mjs" --prompt "猫咪挥手，固定镜头，动作连贯，首尾自然衔接的循环动画" --project "<项目根目录>" --name "挥手猫" --output-format gif --frame-count 9 --frame-duration-ms 200
```

GIF 提示词要同时给动作和循环方式，「挥手」这种静态描述加「循环」不够，上游常按静态图出。只有动作可循环、且写明「首尾衔接 / seamless loop」时，模型才会采样出多帧。

带参考图（走 `/v1/images/edits`）：

```bash
node "<SKILL_DIR>/scripts/generate.mjs" --prompt "<提示词>" --project "<项目根目录>" --image "<参考图路径>"
```

多张参考图重复 `--image`；蒙版用 `--mask`。

| 参数 | 必填 | 说明 |
|---|---|---|
| `--prompt` | 是 | 生图或改图提示词，不含尺寸/质量等控制词 |
| `--project` | 是 | 用户当前项目根目录 |
| `--image` | 改图时必填 | 参考图本地路径，可重复。有此参数即走 edits |
| `--mask` | 否 | 蒙版图本地路径；必须同时有 `--image` |
| `--model` | 否 | 覆盖 `config.json` 的 model |
| `--size` | 否 | `1024x1024` 或 `auto`；与 `--tier/--ratio` 二选一 |
| `--tier` | 否 | `1K` / `2K` / `4K`，默认 `1K` |
| `--ratio` | 否 | `1:1` / `3:2` / `2:3` / `16:9` / `9:16` / `4:3` / `3:4` / `21:9`，默认 `1:1` |
| `--quality` | 否 | 默认 `auto` |
| `--n` | 否 | 张数，默认 1 |
| `--output-format` | 否 | `png/jpeg/webp/gif/svg`；默认不发送，跟随渠道 |
| `--frame-count` | 否 | GIF 帧数，2-16；默认不发送 |
| `--frame-duration-ms` | 否 | GIF 每帧时长，至少 20 毫秒；Responses 上游最多 2000 毫秒，由网关校验；默认不发送 |
| `--output-compression` | 否 | JPEG/WebP 压缩率 0-100；PNG/GIF/SVG 不支持 |
| `--moderation` | 否 | 默认 `auto` |
| `--background` | 否 | 默认 `auto` |
| `--input-fidelity` | 否 | 仅改图；默认不传 |
| `--download-proxy` | 否 | 图片 URL 下载专用的 `http://` 或 `https://` 网络代理，覆盖配置 `download_proxy`；传空字符串强制直连 |
| `--name` | 否 | 短文件名词干。应传主题或角色名；不传则脚本只取提示词开头若干字，再加时间戳 |

`--project` 必须是用户正在工作的仓库根。图片写到 `<project>/temp/images/`。相对路径的 `--image` / `--mask` 先相对项目根解析，再相对当前工作目录。

请求体不发 `response_format`、`stream`；单张时不发送 `n`，多张时发送对应数量。有参考图时 multipart 字段固定为 `image[]`。脚本按返回顺序保存全部图片；返回数量与请求不符时明确报错并列出已保存结果，不自动补发请求。

GIF 不支持蒙版，SVG 仅支持单图；参考图仍须是 PNG/JPEG/WebP/GIF 位图。Responses 渠道的多图限制由网关显式报错，不自动拆成多个请求。请求与 URL 图片下载均有十分钟超时，包含正文读取。

## 配置

从本目录 `config.json` 读取 `url`、`key`、`model` 和可选 `download_proxy`，不走环境变量。`key` 填 `PROXY_ACCESS_KEY`；缺文件时参考 `config.example.json`，请用户补齐实际配置。不要把密钥贴进回复。

`config.example.json` 使用 `gpt-image-2.6-sunburst` 示例；真实 `model` 必须与上游支持或网关模型映射一致。更新技能不改写用户的 `config.json`，测试新模型可用 `--model` 临时覆盖。

`download_proxy` 为空或缺省时直连；例如 `"download_proxy": "http://127.0.0.1:7890"`。只用于下载 `data[].url`，不改变向 `url` 网关发送生图请求的连接。CLI 优先于配置；支持 HTTP(S) 代理，需要 Node.js ≥24.5.0，项目固定的 24.16.0 满足要求。代理连接失败会明确报错，不静默切换直连，也不自动重新生图。不要把含代理认证信息的地址贴进回复。

临时指定图片下载代理：

```bash
node "<SKILL_DIR>/scripts/generate.mjs" --prompt "<提示词>" --project "<项目根目录>" --name "<短词干>" --download-proxy "http://127.0.0.1:7890"
```

## URL 图片返回与下载

- `data[]` 每项有 `b64_json` 或 `url` 都是可处理的图片结果，不要求两者同时存在。脚本优先解码非空 `b64_json`；仅有 `url` 时自动下载、识别实际格式并保存到 `temp/images/`。
- Cloudflare R2 / S3 的 `X-Amz-*` 签名 URL 是正常下载地址，可能带很长的查询参数、百分号编码和过期时间。脚本原样请求完整 URL，不删参数、不解码再拼接、不按 URL 后缀猜格式。不要把临时签名 URL 当成本地交付文件，也不要把网关 key 发给存储服务。
- 下载支持最多 5 次 HTTP 重定向，总超时十分钟，包含重定向和正文读取。URL 过期或权限有问题时可能返回 HTTP 403；DNS、代理、TLS、连接和超时错误会明确报告。
- 失败字段 `generation_completed: true` 表示网关已返回图片结果；`stage: "download"` 表示下载失败，`"decode"` 表示解码或格式识别失败，`"save"` 表示本地保存失败。此时说明实际失败阶段，保留已保存图片，不能笼统说「生图失败」，也不能因下载失败自动重新发起付费生成。

## 脚本结果与用户回复

**读取结果**

- 成功 `ok: true`，`images` 包含全部已保存图片，每项有 `path`、`url`、`name`、`relative`、`bytes`、`format`、`mime`、`revised_prompt`；GIF 另有 `frames`（真实帧数）和 `loop`（是否循环）。顶层保留首图的同名字段；展示多图以 `images` 为准。格式和后缀来自实际文件内容，未知内容明确报错，不用响应标签猜测。
- 成功但带 `warnings` 时，数组里的每条都要在回复中转达：它说明结果与请求不符（格式被忽略、或 GIF 只有一帧）。有 `warnings` 就不能当作完全成功交付。
- `requested_count` / `returned_count` 是请求和实际返回数量。`model`、`endpoint`、`references`、`mask` 是调用信息，默认不展示。
- 失败 `ok: false`，读取 `error` 及可能存在的 `generation_completed`、`stage`。下载失败应说明「网关已返回图片结果，但下载失败」和实际原因。保存部分图片后失败或数量不符时，`images` 列出已保存图片；必须说明未完整完成，不能只展示图片并宣称成功。
- `revised_prompt` 是上游可能返回的改写，不保证存在或等同于实际提交的提示词。用户问实际提示词时，提供本次 `--prompt`，需要时再区分上游改写。

**回复方式**

- **单图成功**：用脚本返回的绝对 `path` 显示图片，例如 `![生成结果](<绝对路径>)`，GIF 同样按图片展示。需要文件链接时使用绝对路径 Markdown 链接；不使用 `file://` 作为预览地址，不编造路径。不重复预览、链接、文件名和相对路径。
- **多图成功**：按 `images` 顺序逐项给出图片入口和绝对路径，可用简短编号区分，不贴整份 JSON。
- **只写提示词 / 反推**：默认只给自然语言提示词代码块；用户要求分析、5S 拆解或参数说明时再提供。
- **失败或部分完成**：简述实际错误和已保存结果，给出明确的处理建议。不自动重试，不改用其他接口。
- **用户要 JSON / 调试 / 提示词**：按所需范围提供，不默认展开全部元数据。未要求时不附提示词全文、5S 检查表或画面复述。任何模式都不贴 base64。
